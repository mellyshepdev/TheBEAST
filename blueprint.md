# **Project: The Beast – Universal Control Plane**
**Role:** Senior Systems Architect & Agentic Developer  
**Objective:** Build a high-autonomy orchestrator that bridges local hardware (**Mac Mini 10.0.0.75, Ubuntu 10.0.0.36, Debian 10.0.0.76**) and Cloud VPS nodes into a single cohesive "Super-Device" [User Document].

### **Step 1: Environment Initialization (Ground Phase)**
Initialize the project workspace with the **Anti-gravity Kit 2.0** to gain access to 16 specialist agents and 40+ pre-built skills [1, 2].
*   **Command:** Open the Anti-gravity terminal and run the MPX installation command for the **Anti-gravity Kit 2.0** [1, 3].
*   **Infrastructure:** Connect **Ollama** as the local engine to run high-reasoning models like **Claude Code** or **Gemma 4B** locally to handle macOS legacy limitations [4-6].

### **Step 2: The "Brain" (Data Ingestion & Global Learning)**
Configure **AnythingLLM** to serve as the private, system-wide memory [7, 8].
*   **Indexing:** Command the agent to "Use the AnythingLLM API to index all documents, images, and config files across the distributed network" [8, 9].
*   **Vector Database:** Implement **PostgreSQL with pgvector** to store metadata (e.g., family birthdays, server logs) for contextual querying [11, 12, User Document].
*   **MCP Integration:** Set the Beast as a bidirectional **Model Context Protocol (MCP)** server/client, allowing external AIs to execute terminal commands on your Mac Mini or Ubuntu nodes [139, 197, User Document].

### **Step 3: The "Hands" (Action & Self-Healing Layer)**
Deploy **Agent Zero** and **OpenCode** as the primary execution frameworks for autonomous system management [10, 11].
*   **ELK Monitoring:** Build a Python-based **Self-Healing module** that monitors Docker containers (specifically the ELK stack) and SSL certificates for `theofficialblacksheepcompany.com` [3, User Document].
*   **Permission Modes:** Implement a toggle in the UI for **[ALWAYS_ASK]** or **[NEVER_ASK_AUTO_HEAL]**. In [ALWAYS_ASK] mode, the Beast must present a "Permission Gate" with verified **Artifacts** (video/screenshots of the fix) before deploying code [29, 171, User Document].
*   **Multi-Session Coding:** Use **OpenCode** to run parallel agents—one for backend architecture on the Ubuntu node and one for frontend UI development [11, 12].

### **Step 4: The "Voice" (Multi-Channel Communication)**
Integrate **OpenClaw** to serve as the omnipresent message bus [13, 14].
*   **Protocols:** Configure gateways for **Matrix (Synapse), Slack, WhatsApp, and SMS** [14-16].
*   **Persistent Memory:** Ensure persona onboarding so the Beast remembers user context across all channels 24/7 [17, 18].
*   **Proactive Action:** Set up cron jobs and "heartbeats" so the Beast can proactively reach out with daily briefings or system health alerts [19, 20].

### **Step 5: The "Spirit" (Personality & Tone Mirroring)**
Utilize the **Agent Skills** update to create a permanent instruction manual for the Beast's behavior [21, 22].
*   **Skill Creation:** Create a folder named `agent.skills` containing a `personality.md` file [23-25].
*   **Mirroring Logic:** Program the **Tone-Mirroring algorithm** to adjust the Beast's energy based on user sentiment [User Document]. 
*   **Accountability:** If a technical error occurs, the Beast must use the **Skill Writer** to document the error, apologize, and explain the automated fix [354, User Document].

### **Step 6: Deployment & Verification (Orbit Phase)**
*   **Vibe Code the Hub:** Use **Flutter/Dart** to build the universal control plane, including a real-time stream of the Beast’s logs and a "Personality Lab" slider [133, 134, User Document].
*   **Live Hosting:** Use the **Netlify MCP** to deploy the control plane to a sharable subdomain for mobile monitoring [26, 27].
*   **Verification:** Run the **Loki mode** autonomous agent to verify every feature (Barcode integration, ELK diagnostics, Messaging) and provide a final video report [28, 29].
